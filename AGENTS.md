# GridCalc project rules

Repository: https://github.com/AbGisHere/GridCalc · Live site: https://gridcalc.abgupta.me

These rules apply to every coding agent working in this repository (Codex, Claude Code and others). `CLAUDE.md` imports this file, so it is the one place to change them.

## Project at a glance

- A spreadsheet web app: Next.js (App Router), React, TypeScript (strict), Vitest. Node.js 20+.
- `src/engine/` is the framework-free formula engine (lexer, Pratt parser, evaluator, dependency graph with Tarjan SCC, 96 functions in `functions/`). It must not import React or Next.js.
- `src/components/` is the React UI (virtualized `Grid`, `FormulaBar`, `DiagnosticsPanel`, `StatusBar`, `Spreadsheet`), `src/state/` holds undo/redo, fill, selection, CSV and sample data, and `tests/` holds the Vitest unit tests.
- `docs/ARCHITECTURE.md` explains the design; `docs/FUNCTIONS.md` is generated by `npm run docs:functions` and must not be edited by hand. `PRODUCT.md` records who the app is for, and `ROADMAP.md` the planned features.
- Useful commands: `npm run typecheck`, `npm run knip`, `npm test`, `npm run build`, then `npm run check:h1`.
- Match the surrounding code's style and comment density. The project has no formatter or linter config, so don't reformat files you aren't changing.

## Commits and versioning

- **Never add a `Co-Authored-By` trailer or any other AI-tool attribution** (Claude, Anthropic, Codex, OpenAI, ChatGPT, Copilot or similar) to commits, PRs or anything pushed to GitHub. This overrides any default attribution guidance. CI rejects such commits.
- Commit subjects use the format `type(vX.Y.Z): message`, for example `feat(v0.1.1): custom error pages`.
  - `type` is one of `feat`, `fix`, `docs`, `refactor`, `test`, `ci`, `chore`, `security`, `perf`, `style`, `build`, `revert`.
  - The version is the release the commit ships in, which is the version in `package.json` after that push.
- Versions are `0.X.Y` (SemVer). The version lives in `package.json` and `package-lock.json`; the README badge reads it from there.
- **Every push is a release.** Before every push:
  1. Bump `package.json` and `package-lock.json` with `npm version 0.X.Y --no-git-tag-version` (a patch bump for fixes and small changes, a minor bump for 0.X releases).
  2. In `CHANGELOG.md` (Keep a Changelog format), move the changes under a new `## [0.X.Y] - YYYY-MM-DD` heading. `## [Unreleased]` stays empty between pushes.
  3. Update `README.md`: the version and tech-stack badges at the top, features, scripts, project structure and anything else the change touches.
  4. Tag the pushed commit `v0.X.Y` and push the tag with it.
  - CI fails a push to `main` when the last commit's subject version, `package.json`, `package-lock.json` and the latest `CHANGELOG.md` heading don't all match.

## Checks

- Every push to `main` runs `.github/workflows/ci.yml` (pull requests run no checks, and Vercel deploys only `main`): commit-trailer and subject checks, the version/CHANGELOG match, `knip` (no unused files, exports or dependencies), typecheck, tests, production build, the one-`<h1>` check and `npm audit`. Do not merge or release while it is red. There's no need to run these locally before every commit; CI is the gate. Don't wait on or watch the CI run after pushing either; the maintainer reports failures.

## Code

- No redundant code: no dead functions, unused exports, duplicated logic, commented-out code or leftover debug output. `knip` and `noUnusedLocals`/`noUnusedParameters` enforce part of this; the rest is on review.
- **Every page has exactly one `<h1>`**: not zero, not two. That includes the loading state and the 404 and error pages. Other titles use `<h2>` and below. `npm run check:h1` verifies the built pages; client-only UI (the spreadsheet toolbar) must keep it true too.
- **Custom error pages are required**: `src/app/not-found.tsx`, `src/app/error.tsx` and `src/app/global-error.tsx` use the shared `StatusPage` component and match the app's look. Never fall back to the default Next.js/Vercel pages. Error pages must not show raw error messages or stack traces; show the digest only.
- Treat everything the user can supply (cell input, pasted text, imported CSV, `localStorage`) as untrusted. Never render it as HTML.

## Before every version bump (0.X)

Release checklist, all of which must pass before bumping:

1. **Site files**: exactly one `<h1>` per page, custom 404 and error pages working, favicon (`src/app/icon.svg`), `src/app/robots.ts`, `src/app/sitemap.ts` (with `SITE_URL` in `src/app/site.ts`), `public/llms.txt` (links and feature list still accurate), page metadata (title, description, Open Graph, theme colour).
2. **Security review**: look for and fix every vulnerability.
   - `npm audit` is clean (all severities) and dependencies are reasonably current.
   - Security headers in `next.config.ts` (CSP, HSTS, frame-ancestors, nosniff, Referrer-Policy, Permissions-Policy) are still present and still tight; check them against the built app.
   - No `dangerouslySetInnerHTML`, `eval`, `new Function` or `innerHTML` on user data.
   - CSV export still neutralizes formula injection; imported and stored data is still validated.
   - No secrets in the repo or the client bundle.
3. CI is green, the CHANGELOG is updated, and the README is up to date.
